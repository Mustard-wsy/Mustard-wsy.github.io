# 总体规划

状态：共享模板已实现，个人网站定位已修订；已通过 GitHub Pages 公网部署。更新日期：2026-10-12。

## 1. 网站的目的

`mustard-wiki` 是作者的个人网站，用于记录自己的笔记、实验和一些喜欢的东西。课程、算法、开发尝试和技术之外的兴趣都可以成为内容，不要求围绕学习成长或正式成果组织。

首页通过简短个人介绍与三个主要入口，让访客认识作者并进入玩具架、文章库、项目目录。「迷途未远」只解释建站初衷，放在关于页，不作为站名或首页标题。

网站应当鼓励记录，不制造额外的打卡压力。内容少时也完整，不以更新频率、文章数量或项目体量证明价值。

## 2. 主要使用场景

| 使用者     | 想做什么                           | 网站提供什么                             |
| ---------- | ---------------------------------- | ---------------------------------------- |
| 作者       | 快速记录一次理解或一个小作品       | 简单的内容文件和统一模板                 |
| 首次访客   | 知道作者关注什么、有什么有趣的作品 | 简短首页、真实文章、玩具预览             |
| 阅读者     | 系统阅读网络课程或算法笔记         | 专题顺序、文章目录、相关文章入口         |
| 项目访客   | 了解用途、效果和实现，找到代码     | 玩具详情、可选媒体、清晰外部链接         |
| 未来的作者 | 回顾旧理解、维护内容               | 稳定地址、按 slug 排列、可追溯的版本历史 |

## 3. 第一版范围

必须有：

- 首页。
- 按文件夹组织的文章库、合集索引、可选专题页和文章详情。
- 玩具架、项目目录及共享的作品详情模板。
- 关于页和可返回主要入口的 404 页面。
- 响应式布局、键盘操作、基本可访问性。
- 代码高亮、数学公式、正文目录。
- 页面标题、描述、分享元数据、站点图和文章 RSS。
- 内容校验、静态构建、GitHub Pages 自动发布流程。

暂缓：

- 评论、账户、数据库、后台管理系统。
- 全站语义搜索、复杂筛选、知识图谱。
- 打卡热力图、连续学习天数、访问量等统计展示。
- 网站桌宠、游戏式导航、必须交互才能访问的内容。
- 双主题切换、多语言。

普通搜索也可在文章增加、浏览开始困难时再加入。第一版通过合集索引、文章列表和可选专题导航完成发现。

## 4. 初期内容组织

### 笔记与兴趣

- 计算机网络：按知识结构组织，允许概念说明、实验记录与理解纠正。
- Hot 100：按解题方法归类，通过独立序号表达专题阅读顺序；不要求每题都写成长文。
- 文章可以脱离专题独立存在，容纳实验记录和喜欢的事物，不强迫所有内容进入课程结构；沿用文章与专题模板，无需新增频道。

### 玩具与项目

“玩具”是作者喜欢的称呼，不代表质量低或不值得展示。水果忍者、Godot 桌宠、SmartFinder 是目前已知的候选内容，具体功能、体积、展示素材和链接在发布前核实。

项目大小不改变页面类型。小玩具可以只有简介与链接，较大项目可以增加架构、取舍、演示和复现说明。需要后端或大型运行环境的项目不要求在线运行。

## 5. 首页的职责

首页是网站入口，通过留白、比例和像素工作台形成吸引力。具体玩具、笔记和专题分别在玩具架与文章库中浏览。

桌面结构为：左侧站名与简短个人介绍、关于入口，右侧玩具架、文章库和项目目录三个入口卡片；窄屏按个人介绍 → 玩具架 → 文章库 → 项目目录排列。首页不展示最近文章、精选玩具、专题列表或内容数量，也不随内容集合是否为空切换布局。

2026-10-09 视觉评审后明确：首页首先用于展示。删除首屏励志标语、页边寄语、通用感悟和大块无图占位，建站动机仅在关于页解释。

2026-10-12 用户明确首页以入口和吸引力为主，本决定替代先前首页展示具体作品与文章的结构。作品媒体与共享速览保留在玩具架，首页不依赖具体内容或样例素材。

## 6. 成功标准

- 两篇文章、三个玩具时，页面看起来完整且自然。
- 新增普通文章或玩具只需增加内容文件与可选媒体。
- 访客从首页可以直接进入文章或玩具，并明确返回路径。
- 长文章在手机与桌面上都容易阅读。
- 关闭脚本后，正文、导航和作品链接仍可访问。
- 不购买域名或服务也能完成第一版发布。
- 页面有一致的个人气质，同时能够容纳以后未知的作品。

这些是设计与验收标准，不是当前已实现的能力。
