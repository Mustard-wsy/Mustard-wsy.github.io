# 工程与维护约定

状态：架构基线已落地为 Astro 7 + TypeScript + npm。更新日期：2026-10-09。

## 1. 架构方向

采用静态生成：内容文件与站点配置 → 构建时校验和渲染 → 静态 HTML/CSS/必要的 JavaScript → GitHub Pages。

GitHub Pages 支持从仓库发布静态网站，GitHub Free 可用于公开仓库。第一版使用默认 `github.io` 地址即可，无需购买域名。依据：[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。具体额度与部署设置在实际部署时复核。

## 2. 选型标准

已选择 Astro 7，以静态 HTML 输出为默认，普通 CSS 管理视觉，无 React/Vue 运行时。内容使用 Astro collections 与 Zod，Markdown 使用官方 Unified 处理器、Shiki 高亮、remark-math 与 rehype-katex。包管理器为 npm，锁文件提交到仓库。

选择依据：[Astro 内容集合](https://docs.astro.build/en/guides/content-collections/)、[Markdown 处理器](https://docs.astro.build/en/guides/markdown-content/)、[GitHub Pages 部署](https://docs.astro.build/en/guides/deploy/github/)。相较于手写内容管线，减少解析和路由维护；相较于引入完整客户端框架，保持阅读路径轻量。代价是依赖 Node.js 构建及 Astro 的升级维护。

未来重新评估框架时，仍按以下标准：

- Markdown、内容 schema、代码高亮、公式和 RSS 的支持方式。
- 静态导出与 GitHub Pages 子路径是否简单可靠。
- 默认客户端脚本体积，是否能按组件添加交互。
- 学习与维护成本，是否容易使用共享模板。
- 构建依赖与更新负担。

不为纯内容网站引入不需要的服务端能力。也不为了减少依赖而从头实现 Markdown 解析器等基础能力。

## 3. 逻辑边界

| 层       | 职责                                     | 不承担                   |
| -------- | ---------------------------------------- | ------------------------ |
| 内容层   | 读取、校验、过滤草稿、排序、解析专题关系 | 具体视觉布局             |
| URL 层   | 统一 site URL、base path、资源与规范地址 | 内容排序                 |
| 页面模板 | 组合内容与组件、生成语义化页面           | 针对某个作品写分支       |
| 共享组件 | 导航、列表项、预览、元信息、正文样式     | 隐式读取全站配置或内容   |
| 样式层   | 设计 token、排版、响应式与状态           | 随意按作品 slug 覆盖样式 |
| 发布层   | 构建产物、部署、环境配置                 | 修改正文内容             |

以清楚的职责边界为目标，不要求机械地为每层创建复杂抽象。

## 4. URL 与部署

- 同时支持用户站点根路径和项目站点子路径，不把 `/` 部署假设写散到组件里。
- 内链、图片、CSS、RSS、站点图与 canonical 都使用统一的 URL 规则。
- 内容页生成可直接访问的静态地址，刷新详情页不依赖客户端路由回退。
- 配置真实站点 URL 后再生成正式 canonical、RSS 和站点图，不发布占位域名。
- 发布流程从默认分支构建；具体分支名与工作流权限在仓库建立后确定。

## 5. 校验与测试

`npm run check`, `build`, `build:demo` 通过 `scripts/astro-isolated.mjs` 执行. 每次在 Git 忽略的 `test-results/astro-<命令>-<随机值>/` 复制源码和内容, 以独立项目根目录生成 `.astro/`, 并把 Vite/Astro 缓存放在该临时目录内. node_modules 只建立目录链接, 不复制依赖. 命令退出后清理本次临时目录, 清理失败时保留并提示路径. 类型检查排除 test-results, 避免扫描测试产物与临时副本.

构建默认输出仍为原仓库 `dist/` 或 `dist-demo/`, 测试与发布显式指定的 outDir 也保持原位置. 测试中的三种构建及两套发布脚本都使用同一隔离入口. 这样本地预览、类型检查与构建不会争用预览项目的 `.astro/content-assets.mjs`, 不靠关闭预览、改系统权限或修改 node_modules 解决问题. 代价是每次复制本地源码与资源, 增加少量磁盘I/O; 大型资源增加后需再评估.

内容校验至少覆盖：

- 必填字段、日期格式与先后关系、slug 唯一性。
- 专题引用存在、专题顺序不冲突、精选顺序不冲突。
- 本地媒体存在，外链格式正确。
- 生产输出不含草稿和预览样本。

实现阶段的重要验证：

- 根路径和子路径各构建一次，检查资源、详情页直达和导航。
- 检查公开文章列表、专题顺序、RSS 与站点图一致性。
- 用少量代表样本验证长标题、无图玩具、代码、公式和空状态。
- 在手机和桌面视口检查布局，键盘走通主要浏览路径。
- 检查基本对比度、焦点、替代文本和减少动态效果。

不为纯静态文案变更增加镜像实现的测试。根据变更风险选择校验，避免堆积重复检查。

## 6. 性能与资源

- 导航与正文无需 JavaScript；交互按需增强。
- 默认不加载完整游戏、引擎运行时、第三方播放器或整套图标库。
- 首屏不依赖远程中文字体、大视频或第三方脚本。
- 预览图设置宽高，非首屏图片懒加载。
- 构建后记录一次实际页面资源与性能基线，再制定适合项目的预算，不预先宣称性能得分。

## 7. 维护原则

- 依赖尽量少，确定包管理器后提交相应锁文件。
- 新功能先检查是否可通过现有模板和可选字段完成。
- 内容模型变更同步更新文档、校验及已有内容，不能留下两套不兼容字段。
- 新增服务或定制组件前说明持续维护成本。
- 内容与素材授权分别考虑，未来选择代码许可证时不要默认涵盖全部个人文章和图片。
- 新页面类型、架构和发布方式等重要变更写入决策记录；普通修文不必写决策记录。

## 8. 选型后需补齐

README 已记录真实命令和环境配置。GitHub 公开个人站仓库已创建，Git 上传、Actions 构建部署与公网页面已验证；计算机网络前三章已于 2026-10-15 手动提交发布，部署重试及公网验证见实施记录。自动发布工具的提交与重试通过临时仓库验证，真实笔记的持续监测上传仍未验证。RSS 和站点图仍待补齐。具体首次配置与日常发布见[托管与日常发布](08-publishing.md)。

## 9. 玩具速览实现

共享 `ToyCard.astro` 输出静态链接和原生 `dialog`；一个去重的小脚本启用速览按钮、控制打开关闭和焦点恢复。不引入客户端框架。公开内容与样例资源的 publicDir 同步切换，媒体校验使用同一个模式。构建测试检查静态回退链接、dialog 目标、子路径和生产素材隔离，替代早期“所有页面零 script”的限制。

## 10. 内容发布与原生 HTML

完整博客发布另用 `npm run publish:site`：按作者选择包含全部未忽略改动，本地格式、类型、测试、正式构建与内链资源检查通过后提交上传，再按提交 SHA 等待 Pages 工作流。遇错立即退出，不自动合并、强推或重试部署。与仅发布内容的工具共用锁，无新增 npm 依赖；状态查询使用 GitHub 公开 API，Node.js 22.21+ 支持环境代理。仅检查用 `--check-only`。具体操作见发布指南。

本地发布工具只提交 `content/`、`public/`，要求网站代码与配置已提交、没有其他暂存改动、本地与远端起点一致。文件稳定后做生产检查、构建及内链资源校验；失败不提交，push 失败保留提交并重试。云端使用官方 Pages actions 和标准 Ubuntu runner，检查通过才部署。监测进程暂不安装系统自启任务。

将已有传递依赖 `rehype-raw` 显式声明为直接依赖，在 URL 改写前解析 Markdown 原生 HTML，解决 HTML 中 `src`、`href`、`poster` 在子路径部署时没有前缀的问题。增加一项维护声明，未加入客户端框架。替代方案是限制作者只写普通 Markdown 或在 HTML 中手写部署前缀，均不符合作者希望自由书写交互且保留部署可迁移性的需求。JavaScript 字符串与 CSS `url()` 不自动改写，应使用相对资源路径。

## 11. 合集与项目目录

`writing-folders.mjs` 从文章原始 filePath 推导所属目录，递归读取 `_collection.json`，校验配置及 Logo，保留公开文章的祖先目录。共享 `WritingDirectory` 渲染根目录及合集索引，使用独立 `/writing/collections/` 路由避免与文章 slug 冲突；统一 URL 层处理中文编码和部署前缀。不引入文件索引数据库或额外依赖。

projects 和 toys 使用同一个 schema、排序校验、卡片、网格、速览和详情组件，频道类型是通用参数，不为具体作品添加分支。发布监测已覆盖整个 content 和 public，新目录与配置无需额外注册。构建测试覆盖嵌套合集、草稿隐藏、稳定文章地址、Logo、子路径以及同 slug 的跨频道路由；独立目录测试覆盖错误配置与缺少 Logo。

## 12. 本地草稿预览

`dev:local` 通过 LOCAL_PREVIEW 开关启动仅监听 127.0.0.1 的 Astro 开发服务器。共享内容层只有在 `import.meta.env.DEV`、开关启用且非 demo 模式时显示草稿；正式 build 即使带有此开关也过滤草稿。页面显示预览提示、noindex，并省略 canonical。没有服务端部署能力或新增依赖，不执行 Git 或发布操作。构建测试刻意设置该环境开关，验证正式产物仍排除草稿。
