## 7.1 无线通信与移动性

无线连接和移动性是两件事. 固定的无线传感器只需要解决无线传输; 笔记本从一个网络换到另一个网络, 即使用的都是网线, 也会遇到地址变化和会话延续问题. **无线(wireless)** 关注链路, **移动性(mobility)** 关注接入位置变化后的通信.

无线网络的基本组成是无线主机, 无线链路, 接入点或基站, 以及连接它们的网络基础设施.

| 模式                              | 特征                         | 例子                                                      |
| --------------------------------- | ---------------------------- | --------------------------------------------------------- |
| 基础设施模式(infrastructure mode) | 接入点连接无线终端与其他网络 | 常见Wi-Fi, 蜂窝网络                                       |
| 自组织模式(ad hoc mode)           | 节点自行组织连接与必要的转发 | 移动自组织网络(Mobile Ad Hoc Network, MANET)              |
| 单跳(single-hop)                  | 终端直接到达接入点或通信对端 | 终端连接家庭AP                                            |
| 多跳(multi-hop)                   | 经过其他无线节点中继         | 无线mesh, 车载自组织网络(Vehicular Ad Hoc Network, VANET) |

有没有 AP 或基站, 与数据是否需要经过多跳, 是两个不同的问题. mesh 网络可以有通向因特网的网关, 自组织网络也不一定与外部网络隔绝.

## 7.2 无线信道为何不同

无线接收端获得的是期望信号与噪声, 干扰和反射信号的叠加.

- **路径损耗(path loss)**: 信号随传播距离和遮挡而减弱.
- **干扰(interference)**: 同频或相邻资源上的其他发送者影响接收.
- **多径传播(multipath propagation)**: 信号经不同反射路径到达, 形成不同延迟与相位, 可能增强或相互抵消.

**信噪比(Signal-to-Noise Ratio, SNR)** 为接收信号功率与噪声功率之比. 用分贝表示时:

$$
SNR_{\mathrm{dB}}=10\log_{10}\frac{P_{\mathrm{signal}}}{P_{\mathrm{noise}}}.
$$

**误比特率(Bit Error Rate, BER)** 是接收到的比特发生错误的比例或概率. 在给定调制编码和信道条件下, 较高SNR通常降低BER; 相同SNR下, 承载更多bit的高阶调制通常需要更严格信号条件.

速率自适应(rate adaptation)在信道变差时选择更稳健, 可能更低速的调制编码, 信道改善时再提高速率. 标称物理速率不等于应用吞吐量, 后者还受共享竞争, 首部, 确认及重传等影响.

### 隐藏终端

```text
A能与B通信, C也能与B通信, 但A与C互相听不到:

A -------- B -------- C
     数据       数据
```

A和C都可能判断本地空闲并向B发送, 在B处发生碰撞, 这称 **隐藏终端(hidden terminal)** 问题. 既可能来自障碍物, 也可能来自距离与衰减, 不要求发送者恰好被一堵墙隔开.

无线发送端自身信号很强, 难以同时检测被衰减的他人信号; 即使能本地监听, 也不知道远端接收者处所有干扰. 因而Wi-Fi不能照搬有线CSMA/CD的边发边检测方案.

## 7.3 CDMA编码与解码

**码分多址(Code Division Multiple Access, CDMA)** 允许多个用户在同一频带同时发送. 每个用户使用不同的码片序列, 接收端据此从叠加信号中取出对应用户的数据. 为了先看清计算, 下面假设各用户理想同步, 接收幅度相同, 并使用正交码.

设用户$i$的一个数据比特映射为 $d_i\in\{+1,-1\}$, 码长$m$, 码向量 $\mathbf c_i\in\{+1,-1\}^m$. 发送向量为 $d_i\mathbf c_i$, 信道线性叠加得到

$$
\mathbf z=\sum_i d_i\mathbf c_i.
$$

若不同用户的码正交, 即 $i\ne j$时 $\mathbf c_i\cdot\mathbf c_j=0$, 且 $\mathbf c_i\cdot\mathbf c_i=m$, 接收端取内积并归一化:

$$
\hat d_i=\frac{\mathbf z\cdot\mathbf c_i}{m}=d_i.
$$

> **例.** $\mathbf c_A=(1,1,-1,-1)$, $\mathbf c_B=(1,-1,1,-1)$, 两者内积为0. A发送1, B发送0, 映射为 $d_A=1,d_B=-1$, 信道向量为
>
> $$
> \mathbf z=\mathbf c_A-\mathbf c_B=(0,2,-2,0).
> $$
>
> 分别与两码求内积再除4, 得到1和-1, 恢复A的1和B的0.

正交性与同步等条件很关键. 实际接收功率不同, 噪声和多径会破坏理想分离, 还需功率控制等机制; 一个用户信号过强可能淹没其他用户, 称近远效应(near-far problem).

## 7.4 802.11网络与接入过程

**IEEE 802.11 无线局域网(Wireless LAN, WLAN)** 通常称为 Wi-Fi. 在常见的基础设施模式下, 一个 AP 和与它关联的终端组成一个 **基本服务集(Basic Service Set, BSS)**.

AP是无线接入设备, 路由器负责跨IP网络转发, 两者功能不同. 家用盒子常将AP, 交换机, 路由器和DHCP集成, 不能由此认为所有AP都会给终端分配IP或执行NAT.

**服务集标识符(Service Set Identifier, SSID)** 是网络名, 不是密码. 一个SSID可以由多台AP提供, 不唯一对应一台物理设备.

### 扫描与关联

| 扫描方式                   | 过程                                               |
| -------------------------- | -------------------------------------------------- |
| 被动扫描(passive scanning) | 终端在信道上接收AP周期发送的beacon, 了解网络和能力 |
| 主动扫描(active scanning)  | 终端发Probe Request, 接收Probe Response            |

终端根据扫描结果选择AP, 完成相应的认证, 关联(association)和安全协商, 再获得或沿用IP配置. 具体安全消息顺序取决于使用的认证方案. **无线关联成功不等于已经有可用IP地址, 也不等于所有身份认证已完成.**

相邻AP选择重叠信道时会共享或干扰无线资源. 更换SSID不能在物理上消除同频竞争, 标称速率也不能直接相加成每个用户的独享带宽.

## 7.5 CSMA/CA, 退避与RTS/CTS

无线发送端很难边发边判断接收端是否发生碰撞. Wi-Fi采用 **带碰撞避免的CSMA(CSMA with Collision Avoidance, CSMA/CA)**: 发送前监听并退避, 发完后等待接收方确认, 没等到ACK再重试.

以下说明经典分布式协调(Distributed Coordination Function, DCF)竞争接入, 不将所有较新Wi-Fi的调度机制简化为这一种流程.

1. 终端监听信道, 等待满足DIFS及必要退避条件.
2. 从竞争窗口(contention window)选择随机退避计数. 信道空闲时按时隙递减, 忙时冻结剩余计数.
3. 信道再次空闲并满足等待条件后继续倒计时, 计数归零才发送整个数据帧.
4. 接收端正确接收普通单播数据帧后, 等待SIFS并发送链路层ACK.
5. 发送端未及时收到ACK, 认为本次尝试失败, 扩大竞争窗口并重试, 直至成功或达到限制.

**分布式帧间间隔(Distributed Interframe Space, DIFS)** 大于 **短帧间间隔(Short Interframe Space, SIFS)**, 使对当前交换的ACK等应答优先于其他终端的新竞争. 具体时长随物理层等条件变化, 不记成所有Wi-Fi统一的微秒数.

广播/组播一般不按普通单播方式逐个接收端发送ACK. ACK丢失也会造成重复发送, 帧序号和重试标志等帮助接收端避免重复交付. Wi-Fi链路层ACK与TCP端到端ACK不同, 前者到AP成功不代表最终服务器收到.

### RTS/CTS预约

隐藏终端可能听不到发送方, 却能听到接收方. 可选的 **RTS(Request to Send)** / **CTS(Clear to Send)** 利用这一点: 发长数据前先交换短控制帧, 让听到预约的其他站暂缓发送.

```text
发送者          接收者/AP          听到预约的其他站
  RTS ------------>
       <---------- CTS                 等待
  DATA ----------->                    等待
       <---------- ACK
```

终端看到 Duration 等字段后, 可以知道接下来一段时间已有通信安排, 于是先不竞争发送. 记录这段占用时间的是 **网络分配向量(Network Allocation Vector, NAV)**, 这种做法称为虚拟载波监听. 隐藏站即使听不到发送者, 只要能听到接收者的 CTS, 也有机会据此避让.

RTS仍可能碰撞, 但短控制帧损失通常小于长数据碰撞. RTS/CTS增加交换开销, 因而不是每帧都使用就一定更快, 也不能解决听不到预约消息的所有干扰.

## 7.6 802.11帧地址与同子网移动

终端发给有线主机的数据, 在无线这一跳先交给AP, 再由AP桥接到分布系统(Distribution System, DS). 无线接收者与最终二层目的端可能不同, 帧中因此需要分别记录这两组地址.

- RA / TA: 当前无线一跳的接收者(Receiver Address)和发送者(Transmitter Address).
- DA / SA: 这次二层数据交付的目的地址(Destination Address)和源地址(Source Address).
- BSSID: 标识基本服务集, 基础设施BSS中通常使用AP相应MAC地址.

以下为常见802.11数据帧的基本地址关系, 具体扩展帧另有定义:

| To DS / From DS       | Address 1      | Address 2      | Address 3 | Address 4 |
| --------------------- | -------------- | -------------- | --------- | --------- |
| 0 / 0                 | DA / RA        | SA / TA        | BSSID     | 无        |
| 1 / 0, 终端发向AP     | AP的BSSID / RA | 终端SA / TA    | DA        | 无        |
| 0 / 1, AP发向终端     | 终端DA / RA    | AP的BSSID / TA | SA        | 无        |
| 1 / 1, 四地址分布转发 | RA             | TA             | DA        | SA        |

例如终端H将数据经AP送到有线默认网关R, 无线帧Addr1为AP, Addr2为H, Addr3为R. 若目的为同二层范围的另一台主机, Addr3可以是该主机, 并非固定必须为路由器. 第四地址也不是仅用于普通ad hoc通信. [IEEE关于四地址转发的说明](https://www.ieee802.org/11/Documents/DocumentArchives/1994_docs/1194248a_scan.pdf)

其他重要字段包括Frame Control, Duration, Sequence Control和FCS. 序号支持去重与重传处理, 不替代TCP的字节序号.

### 同一子网内换AP

终端在同一IP子网的AP之间移动时, IP地址可以保持. 新AP和交换网络更新终端的二层可达位置, 例如通过新位置发出的帧刷新自学习表, 从而继续送往该终端.

如果移动到另一IP子网, 仅让交换机重新学习MAC通常不够, 还需新的地址配置或更高层移动性机制.

## 7.7 速率适应, 省电与Bluetooth

信道变差时, 高速调制可能频繁出错. Wi-Fi根据接收质量或成功反馈调整调制编码, 降低速率有时反而能减少重传, 提高实际吞吐量.

在一种传统省电模式中, 终端通知AP自己准备休眠, AP暂存下行数据; 终端周期醒来接收beacon并检查是否有待收数据, 再决定是否继续接收. 省电减少无线活动时间, 代价可能是增加等待时延. 不同版本还可采用其他调度方式.

**蓝牙(Bluetooth)** 用于短距离个人区域网络(Personal Area Network, PAN). 经典BR/EDR的微微网(piconet)由中心设备协调外围设备, 使用2.4 GHz频段, 时隙调度与跳频(frequency hopping)配合共享介质.

经典BR/EDR基本时隙为 **625微秒**, 基本跳频信道使用79个射频信道. 低功耗蓝牙(Bluetooth Low Energy, BLE)的信道与接入机制不同, 这些参数不能直接套到BLE. [Bluetooth基本带规范](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-62/out/en/br-edr-controller/baseband-specification.html)

## 7.8 4G LTE的组成与协议分层

手机连上基站后, 网络还得确认它是谁, 记录它在哪里, 并在它移动时调整数据路径. **长期演进(Long-Term Evolution, LTE)** 由基站和 IP 核心网中的不同实体分担这些工作, 相关标准由 3GPP 组织制定.

| 实体                                          | 作用                                         |
| --------------------------------------------- | -------------------------------------------- |
| 用户设备(User Equipment, UE)                  | 手机等终端, 运行应用与无线协议               |
| eNodeB / eNB                                  | 4G基站, 调度无线资源, 接入终端, 协助切换     |
| 移动管理实体(Mobility Management Entity, MME) | 控制面注册, 认证协调, 位置与承载管理         |
| 归属用户服务器(Home Subscriber Server, HSS)   | 保存归属用户身份, 订阅和认证相关信息         |
| 服务网关(Serving Gateway, S-GW)               | 用户面数据转发与移动相关锚点                 |
| 分组数据网络网关(PDN Gateway, P-GW)           | 连接外部分组网络, 为相应连接提供IP锚点等功能 |

国际移动用户识别码(International Mobile Subscriber Identity, IMSI)标识用户订阅身份, 与SIM中的长期秘密不是同一个量, 也不是普通IP地址. 身份, 位置和当前通信地址需分别维护.

MME主要处理控制面, 不负责逐个转发所有应用数据分组. 在基本LTE模型中, 用户面大致经过:

```text
UE -- 无线接入 -- eNodeB -- S-GW -- P-GW -- 外部IP网络
                      \ 控制消息与MME, HSS等协作 /
```

### 无线链路协议栈

| 层次                                                     | 主要作用                         |
| -------------------------------------------------------- | -------------------------------- |
| 分组数据汇聚协议(Packet Data Convergence Protocol, PDCP) | 首部压缩, 无线链路相关加密等     |
| 无线链路控制(Radio Link Control, RLC)                    | 分段/重组, 某些模式下的可靠传输  |
| MAC                                                      | 无线资源使用, 调度及相关机制     |
| 物理层                                                   | 将分配资源上的比特编码为无线信号 |

LTE下行使用正交频分复用(Orthogonal Frequency Division Multiplexing, OFDM)等技术, 按时频资源调度终端. 调度器可以考虑信道与业务, 不是所有终端始终平均瓜分一个固定频段.

### 核心网隧道

用户连接到哪座基站会随移动而变化. 核心网用隧道承载用户IP分组, 将基站和网关作为外层端点. 常见封装是GPRS隧道协议用户面(GPRS Tunneling Protocol - User plane, GTP-U), 由UDP/IP承载:

```text
[外层IP | UDP | GTP-U | 用户IP数据报]
```

内层地址表示应用通信端点, 外层地址表示隧道端点. 切换基站时更新隧道端点或相关状态, 外部网络仍按用户原有的IP锚点转发.

## 7.9 5G的主要变化

**5G新空口(5G New Radio, 5G NR)** 通过更灵活的无线资源组织, 大规模多输入多输出(Multiple-Input Multiple-Output, MIMO), 波束赋形(beamforming), 更宽带宽及网络架构改进等提高容量和服务能力.

高频毫米波(millimeter wave)可以提供较宽可用频谱, 但遮挡与覆盖更敏感, 常需更密集部署和定向传输. 5G也使用较低频段, **5G不等于所有连接都使用毫米波**.

峰值速率, 空口时延和容量是在不同条件下衡量的指标, 实际体验还受覆盖, 负载和回传网络影响. 5G核心网也重新划分了功能, 与LTE的实体并非一一对应.

## 7.10 移动性: 身份与位置分离

接入新网络后, 设备可以重新认证并取得连接, 但对端还可能按旧位置发送数据. 移动管理既要处理本地接入, 也要让已有通信跟上位置变化.

**归属网络(home network)** 维护用户长期身份和订阅关系; **访问网络(visited network)** 提供当前接入与位置相关服务. 蜂窝漫游通过归属与访问网络之间的协议协作, 不能只因手机显示有信号就认为已获得归属服务授权.

如果让每次移动都变为全球IP路由更新, 可以概念性地追踪位置, 但大量主机移动会造成状态与更新压力. 更可扩展的方式是保留某个稳定身份或锚点, 单独更新位置绑定.

### 间接路由与直接路由

| 方案                       | 数据路径                         | 优点                 | 代价                                       |
| -------------------------- | -------------------------------- | -------------------- | ------------------------------------------ |
| 间接路由(indirect routing) | 对端 -> 归属锚点 -> 当前访问位置 | 对端不必每次了解移动 | 可能绕远, 形成三角路由                     |
| 直接路由(direct routing)   | 对端获知绑定后直达访问位置       | 缩短绕行             | 对端或相关实体需追踪位置变化并保证绑定可信 |

间接路由中移动端换访问网络后, 注册新的位置, 归属侧将后续分组隧道转送到新位置, 对端可继续使用稳定地址. 移动端回程可经归属侧或采用其他允许方式, 依具体架构而定.

**三角路由(triangle routing)** 中, 对端发往移动端的数据经归属网络绕行. 如果对端和移动端已很近, 仍绕经远处归属网, 代价尤其明显.

## 7.11 LTE注册与切换

以保持P-GW相关IP锚点的连接为例, 注册与承载建立包括:

1. UE发现并选择基站, 建立必要控制通信.
2. 访问网络MME联系归属HSS等, 验证用户并获得服务信息.
3. 建立相应控制状态, 为无线链路协商参数.
4. 配置基站, S-GW, P-GW间的用户面隧道, 使外部数据能抵达当前接入位置.

### 同一蜂窝网络内的基站切换

**切换(handover / handoff)** 需要把无线连接和用户面路径一起迁到目标基站. 以保持IP锚点的切换为例:

1. 源基站根据测量和策略选择目标基站, 请求目标预留资源.
2. 目标确认准备, 源基站指示UE转到目标.
3. UE使用新无线资源, 期间源基站可向目标转交待发数据.
4. 目标通知控制面完成路径切换, 相关网关将隧道出口改到新基站.
5. 确认新路径后释放旧资源.

新无线链路可用与整个核心网路径更新完成不是同一瞬间. 过渡中可能出现丢失, 重排或重复, 协议需处理这些状态. 若保持原IP锚点, 应用可继续看到稳定地址, 不必因每次换基站就重建所有TCP连接.

## 7.12 Mobile IP与上层影响

**移动 IP(Mobile IP)** 为设备保留稳定的归属地址, 再用转交地址记录它当前的位置. 设备移动后更新两者的绑定, 归属代理便可把发往旧身份地址的分组经隧道转交到新位置.

普通 Wi-Fi 在同一子网内漫游时, 通常只需更新二层接入位置, 并不需要这套 Mobile IP 绑定.

无线和移动环境仍可使用TCP/UDP, IP尽力而为模型不变, 但性能会受影响:

- 比特错误导致链路重传或丢包, 切换导致短时中断, RTT与可用带宽变化.
- 经典基于丢失的TCP可能把无线损坏当作拥塞, 降低cwnd, 虽然路径不一定发生了相同程度的排队拥塞.
- 链路重传减少上层丢失, 也可能增加时延和抖动, 影响实时应用和超时估计.
- 若真正改变IP地址, 传统TCP四元组通常改变, 仅靠原连接语义不能自动保持会话, 还需移动锚定或支持迁移的协议机制.
